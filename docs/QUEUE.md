# Build queue: one task at a time

Started 2026-10-23. The order and rules for finishing everything in [PENDING.md](PENDING.md) that is not "after the pilot".
A 20-minute check (a scheduled job in the Claude session) reads this file, finishes the CURRENT task if it is not done,
and only then starts the next. Plan and roles: [AGENT-SESSION-2.md](AGENT-SESSION-2.md).

## Rules (read every time)
1. **One task at a time.** Work only on the task marked `CURRENT`. Do not start the next until the current one is done.
2. **Done means all of:** the build passes; `testStudioDebugUnitTest` passes; the studio build
   is installed on the S9+ and the feature was seen working there (screenshot or `uiautomator` text) or, where the phone
   cannot show it, the reason is written down; PENDING.md and TESTING.md are updated; the task is ticked below with the date.
3. **Phones.** S9+ (100.111.15.33:5555) is mine: check `dumpsys window | grep mCurrentFocus` right before any tap, and stop if
   the studio is not in the foreground. Never install on or drive the S21.
4. **Local model.** For pure logic with a test that decides, write a task card in `tasks/` and run
   `powershell -File tools/agent/run-local.ps1 -Id T-0NN` in the background; review the result, fix by hand if it fails.
5. **No commit, push, publish or server change.**
6. **Honesty.** Nothing is marked as seen working unless it was seen. Write what was not tested.
7. **Status.** Every check ends with two lines to the user: what is done, what is next. When the queue is empty, delete the
   scheduled job and say so.
8. If a task needs the user's decision or the S21, mark it `BLOCKED: <what is needed>` and move on to the next task.
